# 効果的なIDSメタデータの手引き
IDSは、人間とコンピュータの両方が読めるように設計されている。コンピュータに**仕様を**正確かつ正確に記述することが重要であるのと同様に、IDSの受信者に**仕様の**目的、意図、および有用性を記述することも同様に重要である。これは、**仕様の**メタデータを記入することによって達成される。モデル作成者、設計者、エンジニア、クライアント、コンサルタント、その他の利害関係者が、情報がなぜ必要なのか、誰にとって有益なのか、いつ使用されるのかを明確に理解することで、要件が効果的に満たされることが保証される。

## IDSメタデータ
各`.ids`ファイルには、IDS内部にリストされているすべての**仕様に**共通する基本的なメタデータがある。

| 名称 | 説明 | 例 |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| タイトル | IDSの文書タイトルで、IDS全体を指すために使用される。 | "最低納期要件"または"原価計算要件" |
| 著作権 | IDSの著作権者 | "例会社"または"政府部門 X" |
| バージョン | IDS のバージョンは、行われた変更を追跡するためのものである。セマンティック・バージョニングは、X.Yの命名スキームに従ってバージョン管理することを推奨する。Yは、メタデータの変更、説明、スペルミスなどのマイナーな変更を表し、Xは、以前のバージョンでは合格または不合格であったモデルが異なる結果をもたらす可能性のあるメジャーな変更を表す。 | 1."0"または"2.1" |
| 記述 | IDSが誰のために作られるのか、なぜ作られるのか、どのようなプロジェクトに適用されるのか、などをさらに詳しく説明する1つ以上の文章。 | "すべての関係者が基本的な調整とデータスケジューリングを行えるようにするための、すべての OpenBIM プロジェクトの最低要件。モデル共有の前に実行されることが期待され、すべてのプロジェクトのマイルストーンの要件です。"または、"自動化されたモデルベースの数量テイクオフに必要な、コスト見積もりと数量の精度に大きな影響を与える必要なプロパティを指定します。コストプランニングジオメトリガイドラインおよび補強モデリングプラクティスガイドと合わせて読むこと"。 |
| 著者 | IDSの作者（電子メールの連絡先として提供される） | "<john@doe.com>" |
| 日付 | IDSが公表された日付 | "2022-01-01" |
| 目的 | なぜその情報が必要なのか。 | "数量テイクオフ"、"アクセシビリティ分析"、"衝突検出"、"調整"、"コスト見積もり"。 |
| マイルストーン | 情報が必要とされる時、配達のマイルストーン。 | "概略設計"、"建設"、"コミッショニング"、"RIBAステージ3"、"As-built"、"プランニング"、"350"、"400"。 |

## 仕様メタデータ
**各仕様**書には、目標とその達成方法を説明するためのメタデータがある。

| 名称 | 説明 | 例 |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 名称 | どのような情報が指定されているかを示す短い名前 | "壁タイプの命名規則"または"コンクリート数量テイクオフ寸法" |
| ifcVersion | IFCのバージョンは？オプション"ifc2x3, "ifc4", "ifc4x3_add2" | "IFC4X3_ADD2" |
| 識別子 | 追跡、参照、報告を容易にするため、明確で曖昧さのない識別のため。IDSファイル内で一意でなければならない。 | "SP01", "Fire-001","5b1b0426-a21d-4ee9-9b53-e9b7827690a7" |
| 記述 | その要件がプロジェクトにとって重要である理由を記述します。説明を読む人は、なぜその情報が価値を提供するのか、どのワークフローの実現に役立つのか、要件が満たされないとプロジェクトのどのような利益が犠牲になるのかを理解する必要があります。 | "建設リスクを最小限に抑えるためには、原価計算、詳細設計、建物の改修に大きな影響を与える基本的な特性を盛り込む必要がある。" |
| 指示 | 例えば、命名規則がどのように機能するか、適切な値をどのように選択するか、エッジケースではどうするか、といったガイドラインのようなものである。 | "建築家と法規コンサルタントは、この情報を提供する責任がある。複数の値がある場合は、支配的な値を示すものとする。" |
