# スペックはどのように機能するのか？
**仕様**書は、人間が理解しやすいように設計されている。しかし、**仕様書は**、コンピュータソフトウェアが曖昧さのない情報要求を自動的かつ正確にチェックできるように、高度に構造化されている。**仕様**書には、主に3つの部分がある：



1. 説明：仕様の根拠とその達成方法の説明。この部分は、人間が読み、情報が要求されている理由を理解できるように設計されています。


  このフィールドはまた、様々な適用可能性ファセットの根拠を説明するために使用され、それらが個々にではなく、全体として資産に関連するデータ契約を識別するためにどのように役立つかを説明するために使用される。逆に、`description`各要件ファセットのデータは、ユーザが必要とされる個々の情報の目的を理解するのに役立つはずです。

1. 適用可能性：指定しようとしているモデルのサブセットを特定する。IFCモデルにはさまざまなタイプのオブジェクトがありますが、**各仕様は**サブセットにのみ適用されます。サブセットは、エンティティ（例：壁、窓）、クラシフィケーション（例：UniclassEF_25_10_25External walls）などの利用可能なファセットを介して特定することができます。



1. **要求事項**：要求される特性や材料など、適用性で特定されたサブセットに対して要求される情報。

例えば、"*すべての壁が耐火等級を持たなければ*"ならないという**仕様は**、次のような構造になっている：

 1. **説明**: 建築基準法に準拠するためには、壁の耐火等級が重要である。

 1. **適用性**：この仕様は、すべての壁面に適用される。

 1. **要件**：前述の壁対象物は、耐火等級を有していなければならない。

## 仕様書は情報をどのように記述できるか
**適用可能**性と**要件は**、**Facets（ファセット）**コレクションを使用して記述されます。**ファ**セットは、モデル内の単一のエンティティ（壁、ドアなど）が持つ可能性のある情報を記述します。  
**ファセットは**、固定された**ファセット・パラメーターを用いて**情報を正確に記述するため、コンピューターはあなたが求めている情報を正確に理解することができる。

**ファセットが** **適用性の**セクションで使用される場合、モデルの関連部分を特定するために使用する情報が記述される。

**Facetが** **Requirements**セクションで使用される場合、モデル部品が**仕様に**準拠するために満たさなければならない情報制約が記述される。

![IDS Structure](Graphics/ids-structure.png)

情報には6つの異なる**ファセットが**ある：

| ファセット・タイプ | ファセット・パラメータ | 適用例 | 要件例 |
| ------------------ | ----------------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **エンティティ** | **IFC **クラスと** 定義済みタイプ** | IfcWallの"定義済みタイプが"SHEARの"場合に適用されます。 | IfcWall"でなければならず、タイプは"SHEAR"でなければならない。 |
| **属性** | ** **名前と** 価値** | Name"属性の値が"W01"である要素に適用される。 | 値"W01の"属性"Nameを"持たなければならない。 |
| **分類** | ** **システムと** 価値** | "ユニクラス2015で" "EF_25_10_25に"分類される要素に適用される"。 | ユニクラス2015の"分類基準が"EF_25_10_25"であること。 |
| **プロパティ** | **プロパティセット、 名前、 値** | "Pset_WallCommonの"プロパティセットで、"LoadBearing"プロパティが"TRUEに"設定されている要素に適用されます。 | Pset_WallCommon"プロパティに"LoadBearing"プロパティが"TRUEに"設定されている必要があります。 |
| **素材** | **価値** | コンクリート"要素に適用 | コンクリート製"であること |
| **部品** | ** **エンティティと** 関係** | "IfcSpace" に含まれる"要素に適用されます。 | "IfcSpaceに" 含まれて"いなければならない |

**適用性**または**要件の**セクションで複数の**ファセットを組み合わせて**、さまざまな**仕様を**記述することができます。  
一部の**ファセットには**、オプションの**ファセット・パラメータが**あります。  
例えば、あるプロパティが存在することを指定したいが、正確な値は指定したくない場合、**プロパティファセットの**valueパラメータを省略することができます。

**ファセット・パラメータによっては**、有効な値のリスト、数値の範囲、テキスト・パターンを指定することもできます。これらは**複合制限と**呼ばれます。  
例えば、**複合制限を**使用して、火災評価プロパティが値"0HR、"1HR"、または"2HRの"いずれかからのみ選択しなければならないことを指定する。

食欲をそそるいくつかの例を紹介しよう：

| 意図 | 適用性 | 必要条件 |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外壁の耐力壁には、法令に適合する耐火等級が必要である。 | <ul><li>**エンティティ・ファセット****（IFCクラスは** IfcWall）</li><li>**プロパティ・ファセット****（プロパティ・セットは** Pset_WallCommon、**名前は**LoadBearing、**値は**TRUE）</li></ul> | <ul><li>**プロパティファセット****（プロパティセットは** Pset_WallCommon、**名前は**FireRating）</li></ul> |
| 寝室は最低10m2以上の広さが必要 | <ul><li>**エンティティ・ファセット****（IFCクラスは** IfcSpace）</li><li>**アトリビュート・ファセット****（説明文は**テキスト"BEDROOM"を含まなければならない）</li></ul> | <ul><li>**プロパティファセット****（プロパティセットは** Qto_SpaceBaseQuantities、**名前は**NetFloorArea、**値は**&gt;= 10）。</li></ul> |
| すべてのレンガ壁の種類を分類し、承認された命名規則に従わなければならない。 | <ul><li>**エンティティ・ファセット****（IFCクラスは** IfcWallType）</li><li>**マテリアルファセット****（値は**レンガ）</li></ul> | <ul><li>**クラシフィケーション・ファセット****（**システムはUniclass 2015、**値は** EF_25_10で始まること）</li><li>**アトリビュート・ファセット****（Nameは**名前、**Valueは** "WT"01、WT02など、"WTの"後に数字が2つ続くもの）</li></ul> |

**各ファセットが**指定できる各情報の全機能については、以下のセクションを参照してください。

## カーディナリティ
### 適用可能エンティティのカーディナリティ
**各仕様書では**、適用基準に合致するモデルのサブセットが、**「必須（Required）」**、「**任意（Optional）**」、または「**禁止（Prohibited）」**であることを定義しています。次のような例があります：


```txt
applicability =  Type = walls 
                 Property = IsExternal
requirement   =  Property = FireRating
```

以下の解釈が適用される：

| minOccurs | maxOccurs | 解釈 | 意味 |
| --------- | --------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1 | 無制限 | **必須** | IFCモデルには、IsExternalプロパティを持つ壁が少なくとも1つ存在し、そのような壁はそれぞれ耐火等級プロパティを持たなければ*ならない*。 |
| 0 | 無制限 | **任意** | IsExternalプロパティを持つ壁は、モデル内の*オプションで*あり、そのような壁が存在する場合、それらはすべて耐火等級プロパティを持っている必要があります。 |
| 0 | 0 | **禁止** | IsExternalプロパティを持つ壁がモデル内に見つかってはならない。 |

### 要件のカーディナリティ
個々の要件ファセットは、**必須**、**オプション**、または**禁止を**指定することもできます。

次のプロパティのような例がある：

```txt
Requirement 1: Property
    propetySet: ePset_SpaceOMA 
    property: TravelDirection
    datatype: IFCLABEL
```

以下の解釈が適用される：

| タイプ | 意味 | 成功の基準 |
| -------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **必須** | モデルにマッチするプロパティが必要 | 一致するエンティティは、IFCLABEL型でNULLでない値のePset_SpaceOMA/TravelDirectionプロパティを持つ。 |
| **禁止** | 一致するプロパティがモデル内に存在しない | 一致するエンティティのePset_SpaceOMAプロパティセットにTravelDirectionプロパティがありません。 |
| **任意** | propertySet/propertyの期待値と値の制約は定義されていますが、オプションです。 | 一致するエンティティは、そのプロパティを持っていないか、持っていても期待されるデータ型と値である。 |

完全な例として、モデルに耐力壁が含まれないようにしたい場合、耐力壁**禁止（Prohibited**from being load-bearing）の壁エンティティに適用される**Required**指定があるかもしれない。

## IFCスキーマのサポート
**各仕様**書は、適用するIFCスキーマを定義しています。対応するIFCスキーマは以下のとおりです：

- IFC4X3_ADD2
- IFC4
- IFC2X3

IDS は、提供されたIFCモデルに有効なデータのみが含まれていることを前提とします。モデルに構文エラーやIFCスキーマ検証エラーがある場合、モデルを検証できないことがあります。  
作成されたIFCが有効であることを確認するのは、IFCオーサリングソフトウェアの責任である。

## 制限事項
IDSの最初のバージョンは、すべての分野に共通するIFCの基本的な情報と関係を対象としている。  
より高度な情報要件は、現在のところIDSの対象外である。  
例えば、ジオメトリ・チェック、計算値や動的値に依存するチェック、IFCモデル外のデータを参照するチェック、ドメイン固有のIFCリレーションシップを使用するチェックはできません。

ここでは、監査を支援する他のツールを必要とする高度な要件のタイプをいくつか紹介する：

- 構造梁とパイプがぶつからないこと
- すべての壁は敷地境界から3m離す必要がある。
- すべてのオフィススペースの合計面積が300m2以上であること。
- すべてのドアタイプの名前は一意でなければならない
- すべてのポンプは、指定されたサプライヤーとメーカーを持つ必要がある。
- すべてのエアハンドリングユニットには、トリガーイベントを割り当てたセンサーが必要です。
- 土曜日と日曜日は、すべての勤務スケジュールにおいて休日でなければならない
- 主要なソフトウェア・ベンダーは、全モデルを3分以内にロードしなければならない。
- モデル内の関連図面は、CDE の最新リビジョンと一致していなければならない。
- すべての鉄筋はパラメトリックな掃引ディスクとしてモデル化されるべきである。
- 模型は建設時の状態と一致していなければならない。
